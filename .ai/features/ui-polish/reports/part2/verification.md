## Other things I saw
- **The tab bar disappears during a slide from the right** (check 3). This is the one visible break, and it is the "twitch" the slide was meant to remove. The cause is that `slideIn()` in `src/shell/pressed-tab.tsx` translates `[data-slot=page-width]` by +40 px, while nothing on the way up (`.fh-main`, `.fh-app`, body, html) clips sideways overflow (all `overflow-x: visible`). Chromium's mobile viewport then widens the layout viewport to 414–430 px and drops the fixed bar below the screen. A clip on the page's container, for example `overflow-x: clip` in `src/shell/frame.css`, would very likely fix it. I saw it in Chromium's mobile emulation, which uses Android's viewport rules, so Android Chrome and the Android app very likely show it. I could not check iOS. In the store app's web preview (an iframe on a desktop page) it can't show.
- **Admin Home's outline** (check 4) is the old one (`AdminHomeOutline` was not touched in this commit). The 4-number grid, the Partner report card (74 against the page's 104) and the lede line (13 against 22) all differ, so the "Needs you" rows land 31 px lower when the page arrives.
- **After the page scrolls at 1280,** the sticky sidebar sits at 0–766, because `height: calc(100vh − var(--demo-h))` still subtracts the band after the band has scrolled away. The sidebar's foot (the member and the credit) then rests 34 px above the window's bottom instead of at it. It is still readable and the column's colour continues, so this is cosmetic. File: `src/shell/frame.css` (`.fh-side`). Picture: after-web-sam-people-scrolled-1280.
- **The dropdown scrolls the page when it opens** (scrollY 0 → 34 on /admin, 39 on /admin/members, 332 on /people). The before picture (before-web-sam-menu-1280) shows the same, so this predates this part.
- **Keyboard order on a pushed screen:** the back button sits on the bar's left but comes after "Your menu" (on the right) in the tab order, because it lives in `main`. Three Tabs reach "People" after the skip link and the menu. This is minor.
- **Maya's sign-in lands on /today (the founder view) in the store app.** That's existing routing, noted only because the preview started there.
