paper white, a darker paper for boxes, black ink, and rust for warnings only

Changes: the colour values for light and dark (one list each), the headline font (Newsreader, the landing page's serif, self-hosted like today), the app icon (the floor plan with a door gap), and the standard button colour, black. Stays: every screen and part as it is, the body font, each community's own logo and its own chosen brand colour, the made-up portraits.

The detail
  • Colours live in one list of named values per theme at the top of the app's style file. The sign-in, the console, the emails' web views and the demo banner all read from it.
  • Buttons follow the community's brand colour today (the demo's is dark green). A community that set none gets black instead of green. The admin's colour picker keeps its five ready colours and gains black as the first.
  • Newsreader comes as one variable font file (weights 200 to 800, open licence), so titles keep their optical sizes as with Source Serif today.
  • The icon: the door-gap floor plan on an ink square, the landing page's favicon. The "by Village" mark stays Village's.
  • Two automatic tests pin the old colours (they check that every text is readable on its background, in both themes); they are updated to the new colours and must pass.
  • About 2 hours to build, 1 hour to check. A separate checker reads Today, the directory, an intro, the asks board, sign-in and the console, on phone and laptop, light and dark. The demo on this PC gets the new look so the owner can click through it. Undo: revert the pull request.

Qareen recommends building it as planned because the app and its landing page then read as one product, and the change is a value swap, not a redesign.

Does the app move onto this look as shown?

Qareen recommends black for communities that set no colour because it matches the landing page, and a community can still pick its own colour.
